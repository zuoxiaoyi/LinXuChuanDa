# 标签字典与穿搭素材模型设计

## 目标与范围

本阶段为后续“颜色＋天气＋场景匹配穿搭”准备可信数据，完成：

- 后台标签字典维护；
- 穿搭和幸运配饰表单改造；
- 颜色自动推导五行；
- 服务端保存校验和发布校验；
- 旧草稿兼容读取。

本阶段不实现穿搭推荐评分、不修改小程序详情页、不接广告。

## 字典模型

新增集合 `tagDictionaries`，唯一键为 `type + code`。

公共字段：

- `type`：`element/color/scene/season/weather/accessoryType`
- `code`：稳定英文编码，保存后不可修改
- `name`：后台和小程序展示名称
- `order`：排序
- `enabled`：是否可用于新素材
- `systemLocked`：系统项是否禁止删除和改编码
- `colorHex`：仅颜色使用
- `elementCode`：仅颜色使用
- `status/version/createdAt/createdBy/updatedAt/updatedBy/isDeleted/deletedAt`

系统初始化数据：

- 五行：`metal/wood/water/fire/earth`，名称为金、木、水、火、土；锁定。
- 场景：`commute/leisure/vacation`，名称为通勤、休闲、度假；允许新增。
- 季节：`spring/summer/autumn/winter`，名称为春、夏、秋、冬；允许新增。
- 天气：`normal/hot/rain/wind/snow`，名称为常规、炎热、降雨、大风、降雪；允许新增。
- 配饰类型：项链、耳饰、手链、戒指、手表、包、帽子、其他；允许新增。
- 颜色：
  - 木：绿、青
  - 火：红、粉、紫、橙
  - 土：黄、棕、咖、驼、杏、褐
  - 金：白、银、浅灰、金属色
  - 水：黑、蓝、深灰

颜色必须绑定一个五行，色值用于后台预览。停用字典项不会修改历史素材，但不能再用于新建和发布。

## 素材模型

### 穿搭

规范字段：

- `primaryColorCodes`：主色，必填1至3个
- `accentColorCodes`：辅助色，可选
- `elementCodes`：服务端根据主色和辅助色自动推导
- `sceneCodes`：场景，发布时至少1个
- `seasonCodes`：季节，可选
- `weatherCodes`：天气，可选
- `temperatureMin/temperatureMax`：发布时必填，最低温不得高于最高温
- `waterproof/windproof/breathable`：防水、防风、透气
- `inventoryStatus`：`available/unavailable`
- `priority`

季节只用于运营筛选和候选加分；后续算法以温度范围为主要硬条件。天气标签描述适用环境，三个布尔属性用于处理降雨、大风和炎热等硬约束。

### 幸运配饰

规范字段：

- `primaryColorCodes`：至少1个
- `elementCodes`：服务端根据颜色自动推导
- `sceneCodes`：至少1个
- `accessoryTypeCode`：必填
- `priority`

配饰V1不增加季节和天气字段。

## 后台交互

新增“标签字典”页面，按六种类型分组查看、创建、编辑、排序和启停。系统锁定的五行只允许查看名称，不允许删除或修改编码。

穿搭和配饰表单的下拉选项全部来自 `tagDictionaries`：

- 禁止 `allow-create`，避免产生同义脏数据；
- 选择颜色后即时显示推导出的五行，五行不可手选；
- 已停用但被旧素材引用的选项仍显示“已停用”，保存时要求改为启用项；
- 穿搭表单增加防水、防风、透气和库存状态；
- 配饰表单增加配饰类型。

提供一次性的“初始化默认字典”操作，服务端按 `type + code` 幂等写入，不覆盖运营已经修改的名称、色值、排序和启停状态。

## 服务端校验

保存时：

- 校验所有编码存在且启用；
- 根据颜色字典重建 `elementCodes`，忽略客户端传入的五行；
- 校验字段数量、温度范围和布尔值；
- 草稿允许图片、颜色、场景或温度暂缺。

发布时：

- 穿搭要求封面、名称、说明、主色、场景、温度范围和可用库存；
- 配饰要求图片、名称、说明、主色、场景和配饰类型；
- 任一引用字典已停用则拒绝发布并返回具体字段；
- 下架不执行完整性校验。

## 旧数据策略

现有 `sceneTags/colorTags/elementTags/seasonTags/weatherTags` 继续兼容读取，但不再作为新算法输入。旧草稿可以打开，发布前必须在新表单中重新选择标准编码。暂不自动猜测旧自由文本对应关系，避免错误迁移。

列表页对未完成标准化的素材显示“待补标签”，便于逐条清理。

## 安全与审计

- 字典和素材写入继续使用现有管理员权限。
- 字典写操作记录 `auditLogs`。
- 系统锁定字典禁止删除。
- 客户端不能直接指定推导后的五行。
- `type + code` 使用数据库唯一索引防止并发重复。

## 测试与验收

- 默认字典初始化可重复执行且不产生重复项。
- 21种颜色均正确绑定五行。
- 颜色选择变更后，穿搭和配饰五行同步更新。
- 自由输入标签被移除。
- 无效编码、停用编码和错误温度范围无法保存。
- 不完整草稿可以保存，但无法发布。
- 满足必填项的穿搭和配饰可以发布。
- 旧草稿能够打开，列表显示“待补标签”。

## 部署影响

- 新增 `tagDictionaries` 集合及 `type + code` 唯一索引。
- 需要重新上传 `cloudfunctions/adminApi`。
- 需要重新构建并发布 `admin-web`。
- 小程序本阶段无需重新上传。
